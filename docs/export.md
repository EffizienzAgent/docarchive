# Export

**Export archive** ("Archiv exportieren", list view button and **Export** in the counterparty panel, role **Archive Admin** only) builds a self-contained package of archived documents, e.g. for a tax audit, a provider change or a leaving customer. The dialog filters by storage target, own company, document type, date range and counterparty; the counterparty panel prefills its counterparty. Each export is an **Archive Export** record ("EXP-…") with the scope, the user, the progress and the result, and stays as a log after its files expire.

The export runs on the long queue:

- Only one export runs at a time. Starting another one while an export is queued or running is refused.
- The selection uses the requesting user's permissions, so User Permissions on the Archive Admin limit the export.
- It includes documents with an archived copy on the chosen target whose versions are all recorded; others are counted as "Not on Storage Target".
- It reads every recorded version (file, attachments, `.meta.json`, extension sidecars) from storage with the archive key, never from the Frappe file, through `store.download`, the only function that calls `GetObject`. Four objects are fetched in parallel, each streamed to a temp file, retried up to three times.
- Each object's SHA-256 is checked against the recorded checksum (sidecars: against the stored `sha256` metadata). A mismatch or an unreadable object is listed in the record and in `manifest.json` and does not stop the export.
- Above **Export Part Size (MB)** (Archive Settings, default 2048, at most 4096) the export is split into parts, each a complete package. Before each part, it checks the free disk space for that part.
- Each ZIP (ZIP64; PDFs and images stored without compression) is uploaded with `s3storage.backend.insert_file` as a private File attached to the record, in parts and without loading it into memory. Downloads support `Range`, so they can resume.
- After **Keep Exports For (Days)** (default 7) a daily job deletes the files and sets the record to Expired. The same job marks exports that are still queued or running after 7 hours as Failed (the job timeout is 6 hours) and removes their files and temp directories.
- Export files can only be downloaded by users with the role Archive Admin, also by the user who started the export.

Each ZIP contains:

- `documents/<object key>`: the archived objects with their exact bytes. Objects of documents archived under the older key scheme get the current file name in the package (from the frozen archive metadata); `manifest.json` keeps the real object key next to the package path,
- `manifest.json` and `manifest.csv`: scope, every document with its metadata (taken from the archived `.meta.json` or the newest sidecar), retention, lock mode, legal hold, `thread_key` and `thread_root` (the joined conversation; not part of the archived metadata, taken from the database at export time), the counterparty with its type, ID, name and a `Name (ID)` label (in `manifest.csv` as the last column, `counterparty_label`) (from the metadata, or from the database for older archives without it), and per object the key, version ID, SHA-256, size and check result,
- `previews/<path>.html`: for `.eml` files a rendered, sanitized preview with subject, from, to, cc and date (labels always shown), the HTML body or the escaped plain text, and inline images (`cid:`) turned into `data:` images. A Content-Security-Policy blocks scripts and all remote content. The viewer shows the attachments of the mail as chips with their size; inline images that the body shows are not listed again. Mails above 50 MB get no preview,
- `previews/<path>.download.js` and `previews/<path>.files/<n>-<name>.js`: the bytes of each `.eml` and of each mail attachment, which the viewer loads only when you click **Download original** or an attachment. Browsers ignore the `download` attribute for `file:` links: they would show a mail as source text and open an HTML or SVG attachment as a page. So the viewer saves the bytes through a Blob, and if a browser blocks local scripts it says where the mail is in the package. For mails the viewer shows the preview instead of **Open original**. Export parts plan 2.5 times the size of a mail for this,
- `audit/<yyyy>/<mm>/<file>.json`: the audit entries that touched an exported document (in the part with that document), and entries without documents, such as settings changes, within the date range (in part 1), as stored in the bucket. An entry lists every document of its trigger, so it can name documents outside the export. An entry that cannot be read from the target or does not match its checksum is listed as a mismatch and included from the database copy; one not yet written is included from the database copy and marked as such,
- `index.html`: an offline viewer in one file, without network requests. It lists all documents with search and filters (type, counterparty, own company, year, legal hold, problems), shows the metadata and retention trail, previews PDFs, images, XML and mail, and always links the original to open or download. Files that a browser could run (HTML, SVG, XSLT and similar) are only offered as a download. The embedded data escapes `<`, `>`, `&`, U+2028 and U+2029, so no document text can end the script block. Documents with a `thread_key` show their conversation, newest first. Mails are grouped by `thread_root` (falling back to `thread_key`), so a conversation whose mails got different keys from their mail clients stays together (see [Threads and gaps](correspondence.md#threads-and-gaps)). The metadata block always shows the same fields with labels (empty ones as "–"), so the file starts at the same position for every document; the counterparty shows as `Name (ID)` with its type. Keyboard: j/k or ↑/↓ move through the list, Enter opens the preview, `/` focuses the search, Esc clears the search or closes, ←/→ switch attachments and `?` shows all shortcuts; none of them fire while typing. Under "Export Viewer" in Archive Settings you can set a brand name, a logo (PNG, JPEG, GIF or WebP up to 200 KB, embedded as a data URI) and a hex accent color, and turn off the "Made with docarchive" footer link. Without these the viewer stays neutral. The **Audit Log** tab lists the entries with search and an action filter and links each document; each document lists its entries and links to them.
